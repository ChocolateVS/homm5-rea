# Combat audit — sweep 11: Exploding Corpses, creature spell power, damage queue, Howl / Imbue Arrow / Obsidian traces

Per-ID rows merged into `docs/rules/AUDIT_COMBAT.md` by `tools/re/audit/ledger.py` (fragments are read in natural
order, so rows here override sweep 1–10). Exe references are H5_Game.exe (GOG 3.1) addresses, analysed headless with
Ghidra 12.1.4 (private project copy), disassembly read directly where the decompiler loses registers. Tests are in
`tests/H5.Combat.Tests/AuditSweep11Tests.cs`; code in `src/H5.Combat/Battle.Sweep11.cs`.

Facts used below. A combat unit's live count / top health is the last 12-byte record of the vector at stack +0x1c /
+0x20 (creature +0xb0; FUN_008ace20, the empty vector reads a static zero record); the damage handler (unit vf 0x1f4 =
FUN_008a6e20) stores count ceil(hp / health) — 0 once the health is gone — and the heal handler vf 0x1f8 =
FUN_008a7780 reads it back. The creature's unit interface is the virtual base at +0x148 (vtable 00e4fba4: vf 0x28c =
008aece0, vf 0x1f4 = 008aed70 → 008a6e20, vf 0x1f8 = 008aed80 → 008a7780). CCombat (RTTI 00f73d14, primary vtable
00e79d3c) keeps a deferred damage queue at +0xdc (FUN_008d7f10 → FUN_008d7c90, interface vtable 00e5361c): vf 0 =
FUN_008d7e70 / vf 4 = FUN_008d7ec0 push a 0x30-byte record through FUN_008d7da0 {+0 time, +4 damage, +8 attacker,
+0xc target, +0x10, +0x18 flag, +0x1c, +0x20 spell, +0x24 flag, +0x28, +0x2c kill count} and return the time
unchanged; vf 8 = FUN_008d7f40 flushes it (per record, target alive: FUN_00a616e0(target, time, &damage, 0 or the
attacker, 0, +0x1c, attacker) for a damage, FUN_00a61530 for a kill count × health).
